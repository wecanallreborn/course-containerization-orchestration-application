\section{Первый рабочий образ}

Клонировали репозиторий с готовым приложением.

\begin{code}
git clone https://github.com/FilBTi/assist-py solutions/assist-py
rm -rf solutions/assist-py/.git
cd solutions/assist-py
\end{code}

Создали docker файл в корне проекта assist-py. Написали конфигурацию базового образа.

\begin{code}
FROM python:3.11-slim
LABEL maintainer="manuk@lab.local"
LABEL version="1.0"
WORKDIR /app
ENV PORT=5455
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
EXPOSE ${PORT}
CMD uvicorn app.main:app --host 0.0.0.0 --port ${PORT}
\end{code}

Собираем образ при помощи команды.

\begin{code}
docker build -t manuk-assistant:v1 .
\end{code}


Запускаем контейнер с переменным окружением и персональными параметрами.

\begin{code}
docker run -d \
  --name manuk-assistant-1 \
  -p 5455:5455 \
  -e APP_OWNER=manuk \
  -e APP_SECRET=secret25manuk \
  manuk-assistant:v1
\end{code}

Проверяем при помощи команд работоспособность контейнера, созданного по ранее написанному образу. Терминальный вывод представлен на рисунке \ref{fig:1}.

\begin{code}
curl http://localhost:5455/
curl http://localhost:5455/me
curl -X POST http://localhost:5455/notes \
  -H "Content-Type: application/json" \
  -d '{"text": "ЛР2: сборка образа"}'
curl http://localhost:5455/notes
curl http://localhost:5455/secret/secret25manuk

\section{Оптимизация образа}

Для уменьшения размера были уже добавлены следующие строчки в изначальный файл. В новой версии поставим без флага кэша.

\begin{code}
RUN pip install --no-cache-dir -r requirements.txt
\end{code}

Проверим насколько флаг влияет на вес образа.

\begin{code}
docker build -t manuk-assistant:v2 -f Dockerfile.optimized .
docker images | grep manuk-assistant
\end{code}

На 12.3MB образ с флагом оказался больше. (рисунок \ref{fig:v12})

\reportscreenshot{pic/v12.png}{Результат работы команд}{fig:v12}

При изменении слоя докер пересобирает все слои с него и ниже по коду (выше по слоям). То есть при изменении любых файлов будут заного переустанавливаться библиотеки из requirements, тк эта команда выполняется после измененного слоя. Копируя отдельно файл, предотвращается эта проблема. Для ранее выполненны теже команды, то в логах CACHED и они не выполняются повторно.  

\section{.dockerignore - чистота в образе}

Cоздали в корне проекта файл .dockerignore.

\begin{code}
__pycache__/
*.pyc
*.pyo
.git
.gitignore
.venv/
venv/
.env
*.log
Dockerfile*
README.md
\end{code}

Далее собрали новый образ без этих файлов. 

\begin{code}
docker build -t manuk-assistant:v3 .
\end{code}

Файлы гита создают потенциальную опасность из-за хранения всей истории коммитов, при неосторожности: если были закоммичены файлы с чувствительными данными, они останутся там.
Без .dockerignore выгружаются файлы виртуального окружения, логи, сам Dickerfile (который уже не нужен), файлы гита, а так же секреты .env, что недопустимо.

\section{Healthcheck - готовность к оркестрации}

Добавили в Dockerfile.optimized (добавив и удаленный флаг ). Ставим curl для самопроверки контейнера изнутри (в слим версии этой команды нет), все выполняется одним run для удаления списка пакетов в одном слое, для оптимизации веса также ставятся лишь обязательные пакеты.

\begin{code}
RUN apt-get update \
    && apt-get install -y --no-install-recommends curl \
    && rm -rf /var/lib/apt/lists/*

HEALTHCHECK --interval=30s --timeout=5s --start-period=10s --retries=3 \
CMD curl -f http://localhost:${PORT}/health || exit 1
\end{code}

Собираем финальный образ и сравниваем вес (рисунок \ref{fig:f}).


\begin{code}
docker build -t manuk-assistant:final -f Dockerfile.optimized .
docker images | grep manuk-assistant
\end{code}

\reportscreenshot{pic/f.png}{Результат работы команд}{fig:f}
